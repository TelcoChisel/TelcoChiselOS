TelcoChisel — Telecom Security Linux Distribution

Bootable live OS for 5G/4G security research, SDR analysis, and baseband auditing

TelcoChisel is a free, bootable live Linux distribution purpose-built by TelcoSec for telecom security auditors, 5G Standalone (SA) and O-RAN penetration testers, baseband vulnerability researchers, and Software Defined Radio (SDR) engineers. Based on Ubuntu 24.04 LTS (Noble Numbat) with a 1000Hz Low-Latency Kernel, it ships with 100 pre-configured tools across 11 functional domains covering SDR drivers, 5G core simulation, baseband emulation, SIM auditing, and telecom protocol fuzzing — ready to use without installation.

Frequently Asked Questions

What is TelcoChisel?
TelcoChisel is a free, bootable live Linux distribution based on Ubuntu 24.04 LTS with an XFCE desktop, purpose-built for telecommunications security research. It includes 100 pre-configured tools across 11 domain suites for Software Defined Radio (SDR) analysis, baseband firmware auditing, SIM and eSIM inspection, and 5G/4G core network penetration testing — no installation required.
What SDR hardware does TelcoChisel support?
Drivers compiled from source for the Ettus Research USRP B210, Great Scott Gadgets HackRF One, Nuand BladeRF 2.0 micro xA4, LimeSDR, and RTL-SDR dongles. All SDR drivers and GNU Radio are sandboxed in a Conda environment named telcosec-sdr to prevent system Python conflicts.
Can I run TelcoChisel in a virtual machine?
Most analysis and protocol tools work in a VM. However, SDR tools that stream high-bandwidth samples — particularly the 5Ghoul 5G NR fuzzer — require bare metal installation with native USB 3.0 passthrough for reliable operation. Running inside VirtualBox or VMware will cause USB overrun errors.
How do I install 5Ghoul for 5G NR fuzzing?
All build dependencies are pre-installed. Run sudo 5ghoul-install for a USRP B210, or sudo 5ghoul-install --radio BLADERF for a BladeRF A4. The installer clones the repository, applies radio patches, and compiles OpenAirInterface. Allow 20–60 minutes for compilation. See the 5Ghoul Fuzzing guide in this documentation for the full workflow.
What telecom protocol tools are included?
Protocol scanners: sctpscan (SCTP/S1AP/NGAP/Diameter), SIPVicious (SIP/VoIP). Exploitation: SigPloit (SS7/Diameter/GTP), Diafuzzer (Diameter). Packet analysis: Wireshark with custom GSMTAP, 5G NAS, Diameter, and GTP column profiles; Scapy with M3UA, TCAP, and MAP modules. Core network: Open5GS (5G SA), srsRAN (4G/5G RAN simulator).
What are the default live boot credentials?
Username: telcosec — Password: telcosec. The system is configured for graphical autologin; you will only be prompted if autologin has been disabled.

OS Customizations & Kernel Tuning for Telecom Security

Real-time scheduling, SCTP stack tuning, and low-latency USB for SDR and signaling tools

Telecom software suites (like srsRAN, OAI, or SigPloit) place extreme demands on kernel timers, socket memory buffers, and transceiver streaming rates. TelcoChisel applies specific kernel and PAM optimizations by default.

1. Real-time Scheduling (PAM & Groups)

Software Defined Radios require consistent scheduling intervals to avoid sample drops (under/overruns). Under standard Linux settings, non-root users cannot request real-time execution priority.

/etc/security/limits.d/99-realtime.conf
# Enable real-time scheduling priority up to 99 and unlimited locked memory
@realtime       -       rtprio          99
@realtime       -       memlock         unlimited

The default user telcosec belongs to the system realtime group, enabling GNU Radio and srsRAN threads to lock samples into physical RAM and run at scheduling priority 99.

2. Kernel SCTP Stack Optimizations

SCTP (Stream Control Transmission Protocol) is the transport layer backbone of telecom networks (SS7/M3UA, Diameter over SCTP, S1AP, and NGAP). Standard OS kernels are optimized for TCP/UDP. TelcoChisel preloads the kernel SCTP module and tunes socket limits in /etc/sysctl.d/99-sctp-tuning.conf:

SCTP sysctl parameters
# Increase buffer limits for telecom signaling
net.sctp.sctp_mem = 94500000 915000000 927000000
net.sctp.sctp_rmem = 4096 87380 8388608
net.sctp.sctp_wmem = 4096 16384 8388608

# Tuning retransmission timeouts (prevent scanner hangs)
net.sctp.rto_min = 200
net.sctp.rto_max = 800
net.sctp.association_max_retrans = 4
net.sctp.path_max_retrans = 2

3. Low-Latency USB & GRUB Configurations

To run high-bandwidth 5G NR Rogue Base Stations, USB polling jitter must be eliminated. The system deploys udev rules to turn off autosuspend delay on USRP B210 and HackRF hardware:

/etc/udev/rules.d/51-usb-latency.rules
ACTION=="add", SUBSYSTEM=="usb", ATTR{idVendor}=="2514", ATTR{power/autosuspend_delay_ms}="0"
ACTION=="add", SUBSYSTEM=="usb", ATTR{idVendor}=="2514", ATTR{power/control}="on"
ACTION=="add", SUBSYSTEM=="usb", ATTR{idVendor}=="1d50", ATTR{power/control}="on"

Additionally, GRUB configs disable CPU mitigations (mitigations=off) and set the clocksource to TSC for stable timing on bare metal installations.

6. Dual Low-Latency Kernel & Multi-Boot Architecture

TelcoChisel boots by default with the Ubuntu low-latency real-time kernel (linux-image-lowlatency), providing sub-millisecond timer granularity essential for high-throughput 5G NR and LTE frames. The live GRUB bootloader supports four operational profiles:

  • Standard Live Mode: Full XFCE desktop environment with real-time DSP audio/RF scheduling.
  • Encrypted Persistence Mode: Automatically discovers and mounts a LUKS-encrypted casper-rw partition for sensitive field data.
  • Lightweight i3 Tiling Mode: High-performance keyboard-driven window manager minimizing RAM consumption on field laptops.
  • Toram Mode: Copies the squashfs filesystem directly into RAM, maximizing I/O speed and allowing the live USB to be disconnected.

SDR Drivers & Hardware Access — USRP, HackRF, BladeRF, LimeSDR, RTL-SDR

Non-root USB access for SDR transceivers and smartcard readers via custom udev rules

Traditional security environments force you to run RF interfaces as root to access raw USB descriptors. TelcoChisel utilizes custom udev permissions, allowing members of the standard `plugdev` group to read and write directly to transceivers.

1. Non-Root Hardware Access Rules

The file /etc/udev/rules.d/50-telcosec-hw.rules maps USB product and vendor codes, assigning ownership group to `plugdev` and opening permissions:

udev Vendor / Product Maps
# RTL-SDR Dongles
SUBSYSTEMS=="usb", ATTRS{idVendor}=="0bda", ATTRS{idProduct}=="2832", MODE:="0666", GROUP:="plugdev"
# HackRF One
ATTR{idVendor}=="1d50", ATTR{idProduct}=="6089", SYMLINK+="hackrf-%k", MODE:="660", GROUP:="plugdev"
# Ettus USRP B-Series
ATTRS{idVendor}=="2514", ATTRS{idProduct}=="0002", MODE:="0660", GROUP:="plugdev"
# Osmocom SIMtrace 2 sniffer
ATTRS{idVendor}=="1d50", ATTRS{idProduct}=="60e3", MODE:="0660", GROUP:="plugdev"

2. Software Defined Radio (SDR) Drivers Sandbox

GNU Radio and hardware transceiver drivers are isolated in a custom Conda environment named telcosec-sdr. This prevents host apt-package scripts or pip executions from breaking driver configurations.

To execute commands that require UHD, HackRF, LimeSDR, or SoapySDR bindings, activate the virtual environment:

Activate Conda Environment
# Activate sandbox
conda activate telcosec-sdr

# Verify SoapySDR driver bindings are visible
SoapySDRUtil --find

5Ghoul — 5G NR Baseband Fuzzer Setup Guide

Install, configure, and run the 5Ghoul fuzzer against 5G NR UE modems using USRP B210 or BladeRF A4

5Ghoul is a 5G NR baseband fuzzer. It uses an OpenAirInterface (OAI) rogue base station implementation to transmit malformed RRC, NAS, and MAC messages over the air, uncovering vulnerabilities in smartphones, baseband modems, and IoT modules.

Compile Deferred to First Run
To avoid inflating the ISO size and build times (compiling OAI libraries takes over 30 minutes), the framework dependencies are pre-installed in the OS, but the cloning and compiling steps are deferred to first execution. **Do not run 5Ghoul inside a Virtual Machine; it requires native USB 3.0 throughput to stream RF.**

Deploying 5Ghoul on your Live System

1
Execute the Installer
Run the installer helper. Provide the radio backend parameter to target either your USRP B210 (default) or a BladeRF micro A4.
Compile for Hardware
# Option A: Compile for USRP B210
sudo 5ghoul-install

# Option B: Compile for BladeRF A4 (performs patch translations)
sudo 5ghoul-install --radio BLADERF
2
Start the Core Network
5Ghoul simulates the radio interfaces, but requires an active mobile core database to process cellular attachment. Launch Open5GS services and add the default test credentials to the network subscriber database:
Setup 5G Core Subscriber
# Start local 5G SA core functions
sudo open5gs-start

# Register test subscriber profile
sudo 5ghoul-add-subscriber
3
Run the Fuzzer
Connect your SDR to a USB 3.0 port on the host, place the test smartphone inside an RF shield box connected via coaxial cable, and boot the fuzzer.
Launch Fuzzer Engine
# Run NAS fuzzer suite
sudo 5ghoul-run --Attack.Name=NAS_5GS_Fuzz --UE.IMSI=001011234567890

Core Repositories

SctpX Rust

A high-performance, multi-threaded SCTP protocol scanner and interface auditing framework written in Rust. Designed specifically to map cellular core signaling surfaces (SIGTRAN, M3UA, S1AP, NGAP, Diameter) and audit link capacity.

Repository: github.com/TelcoSec/SctpX
TelcoChisel Shell / Config

The official build ecosystem for compiling this custom XFCE Debian/Ubuntu live ISO. Contains baseband configurations, customized system-wide Wireshark columns, real-time udev configs, and kernel tuners.

Repository: github.com/TelcoChisel/TelcoChiselOS
TelcoSec Wordlists Data

Telecom-specific wordlist collection bundled in the ISO at /usr/share/wordlists/telecom/. Covers carrier APNs, VoIP/SIP credentials, RAN element passwords, SIM OTA test keys, hardware defaults, PLMNs/IMSI prefixes, and protocol-level lists for 5G NAS, GTP, SS7, Diameter, SMS, and USSD. Helper scripts telcosec-apn-permutator and telcosec-imsi-generator are available on PATH.

Location: /usr/share/wordlists/telecom/
Downstream Security Patches Forks

Optimized downstream forks of critical security tools such as FirmWire (modified QEMU fuzzers), lpac (enhanced eSIM LPA profiles), and QCSuper (Noble Numbat USB descriptor fixes).

Repositories: github.com/TelcoSec
